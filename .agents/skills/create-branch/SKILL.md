# Create Branch（建立工作分支）

依這門課的命名慣例，替使用者的任務取好分支名稱，從 `main` 建立工作分支並切換過去。

## 核心原則：一個分支＝一個任務

一條工作分支從頭到尾只完成一件事。如果使用者描述的任務其實包含多件不相關的事，先提醒他拆開，一次只為其中一件事開分支——這樣分支名稱才取得精準，日後也好審核、好回溯。

## 命名規則

格式：`類別/英文簡短描述`

1. 類別（四選一）：
   - `feature`：新增或變更功能、內容
   - `fix`：修正錯誤（bug）
   - `docs`：只改文件、說明
   - `chore`：雜項維護（例如整理設定、更新工具），不影響實際功能
2. 描述：英文小寫、單字之間用連字號 `-` 連接（kebab-case），不要有空格、中文或大寫——分支名稱會出現在指令和網址裡，這種寫法最不容易出問題。
3. 光看分支名稱，就要能大致猜到這條分支在做什麼。

## 執行步驟

1. 確認目前站在 `main` 上（`git branch`）；若不在，先切回 `main`。每次都從 `main` 開新分支，因為它是最新、最穩定的正式版本，從它長出來的分支才會包含所有已合併的成果。
2. 依使用者描述的任務，照上面的規則取好分支名稱。
3. 建立並切換過去：`git switch -c 分支名稱`。
4. 回報建立好的分支名稱，讓使用者知道自己現在站在哪條分支上。

## 範例

| 任務 | 分支名稱 |
| --- | --- |
| 將 W1 進度標記為完成 | `feature/mark-w1-completed` |
| 修正登入按鈕顏色 | `fix/login-button-color` |
| 更新 README 說明 | `docs/update-readme` |

不好的分支名稱：`test`、`update`（看不出在做什麼）、`我的分支`（含中文與空白）、`mark-completed-and-fix-typo`（一條分支塞了兩件事）。
