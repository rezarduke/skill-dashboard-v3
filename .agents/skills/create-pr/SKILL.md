# Create PR（準備拉取請求內容）

依這門課的慣例，替使用者目前的工作分支準備拉取請求（PR）的標題與內文，寫成一份草稿檔讓他直接複製到 GitHub 使用。

## 內容規範

1. 標題（Title）：一句中文講清楚這個 PR 要做的事，通常可以把提交訊息去掉類別前綴、調整成完整的一句（例如「將 W1 進度標記為完成」）。
2. 內文（Description）：固定用三個小標題撐起結構，每段用條列式，寫給審核的人看：

   ```markdown
   ## 這次改了什麼
   - （列出實際的改動）

   ## 為什麼要改
   - （說明改動的原因或目的）

   ## 怎麼驗證
   - （說明怎麼確認這次改動沒問題）
   ```

## 執行步驟

1. 先看清楚這條分支相對於 `main` 改了什麼：`git log main..HEAD --oneline` 與 `git diff main`。
2. 依「實際的改動」產生標題與三段式內文，不要憑空猜測。
3. 在專案根目錄寫出草稿檔 `pr-draft.md`：第一行放標題，空一行後接三段式內文。
4. 告訴使用者：到 GitHub 開 PR 時，把標題貼到「Title」欄、三段式內文貼到「Description」欄。

## 注意事項

- `pr-draft.md` 只是給使用者複製用的草稿，不要把它加入提交（commit）；PR 合併後即可刪除。

## 範例

以「將 W1 進度標記為完成」這個任務為例，`pr-draft.md` 的內容會像這樣：

```markdown
將 W1 進度標記為完成

## 這次改了什麼
- 把 data.js 中 W1 的 completed 從 false 改成 true

## 為什麼要改
- W1 的實作練習已經完成，讓儀表板正確顯示為已完成

## 怎麼驗證
- 打開儀表板，確認 W1 顯示為「已完成」
```
